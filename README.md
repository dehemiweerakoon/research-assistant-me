# Research RAG Client

A React and Vite client for searching scientific papers, ingesting research topics, and asking questions about uploaded research papers using retrieval-augmented generation (RAG).

## Features

- User registration and login
- JWT-authenticated API requests
- Explore and search research papers
- Semantic paper search
- Research paper ingestion
- Admin user management
- **Ask** chat powered by the Google Gemini API
- **Research Assistant** workspace for:
  - Uploading multiple PDF research papers
  - Uploading files sequentially through the backend
  - Asking questions across uploaded papers
  - Displaying RAG-generated answers
  - Displaying expandable source excerpts and similarity scores
  - Rendering Markdown-style headings, bold text, and bullet lists

## Tech Stack

- React 19
- Vite
- Axios
- Lucide React
- Google Gemini API

## Requirements

- Node.js 18 or newer
- npm
- A running Research RAG backend on port `5000`, unless configured otherwise

## Installation

```bash
npm install
```

## Environment Variables

Copy the example environment file:

```bash
copy .env.example .env
```

Then update `.env`:

```env
VITE_GEMINI_API_KEY=your_gemini_api_key
VITE_API_URL=http://localhost:5000/api
```

`VITE_API_URL` is optional. If it is not provided, the client uses:

```text
http://localhost:5000/api
```

The Gemini key is used by the standalone **Ask** page. Vite variables are exposed to browser code, so do not use a sensitive production key in this client. For production, Gemini requests should be made through the backend.

## Backend API Contract

The client expects the backend API to be available under `/api`.

### Authentication

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me
```

The client stores the returned JWT in `localStorage` under the key `token` and sends it as a bearer token on subsequent requests.

### Research Paper Operations

```text
GET  /api/papers?q=<query>
GET  /api/papers/semanticSearch?q=<query>
POST /api/papers
```

### Research Assistant Upload

```text
POST /api/suggestions/upload
```

The request uses `multipart/form-data` with one file field:

```text
file=<research-paper.pdf>
```

The Research Assistant accepts PDF files up to 25 MB. When multiple files are selected, the client sends them one at a time and shows the status of each upload.

### Research Assistant Query

```text
POST /api/suggestions/query
```

Request body:

```json
{
  "question": "What approach does this research use?"
}
```

Expected response:

```json
{
  "question": "What approach does this research use?",
  "answer": "The research uses ... [Source 1].",
  "sources": [
    {
      "source": "Source 1",
      "paper_id": 65,
      "chunk_id": 123,
      "chunk_index": 0,
      "similarity": 0.91,
      "content": "Relevant research excerpt..."
    }
  ]
}
```

The Research Assistant displays the `answer` and lets users expand each returned source to inspect its supporting excerpt.

## Application Navigation

After signing in, the left navigation provides:

- **Ask**: Direct Gemini chat with optional file context
- **Research**: Upload PDFs and ask questions using the backend RAG API
- **Explore**: Search and browse papers
- **Semantic**: Perform semantic paper searches
- **Ingest**: Fetch and index papers by topic
- **Members**: Manage users when signed in as an administrator

## Development Notes

- The Vite development server proxies `/api` requests to `http://localhost:5000`.
- The Research Assistant does not send PDF contents directly to Gemini from the browser. PDFs are sent to `/api/suggestions/upload`, where the backend can process and index them.
- Research answers are generated by the backend `/api/suggestions/query` endpoint using the indexed chunks.
- The client preserves source citations returned by the backend, such as `[Source 1]`.
